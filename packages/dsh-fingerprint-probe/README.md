# dsh-fingerprint-probe

DSH 侧栏插件：判断一条 API 路由**实际**在服务哪个模型。

不问模型「你是谁」——自我声明等于网关配置，随时可被系统提示词改写。它让模型写几百个「随机」整数，再拿取值分布去比对参考库。语言模型不是均匀采样器：偏好的数值、区间和末位数字足够稳定，可以用来排名候选。

> 结果说明：这是**在参考库 58 个模型里的相对排名**，不是身份证明。库外模型同样会得到一个最接近的候选与置信度，因为置信度是库内闭集相对概率。适合用来发现「声称 A、实际像 B」这类偏差，不适合断言某个模型一定是什么。面板把这段话放在结果旁边，而不是脚注里。

## 它做什么

1. 生成 3 条挑战：条数从 292–332 随机取且互不相同，语言在中文／英文／日文／韩文／法文中各自独立抽取，并要求模型不得借助任何工具或代码。
2. 通过 DSH 自己的 `ctx.llm` 路由请求——走的就是 agent 平时走的那条路（含鉴权、推理档位、限流），而不是另起一套 HTTP。
3. 解析回复里最长的一段 1–355 整数，按上游判据要求有效数量 ≥ `max(80, ⌈0.55 × 目标⌉)`。
4. 三条都有效时，用冻结的参考检测器排名并给出校准置信度；不足三条则明确标记为「部分样本」，不附置信度。

## 安装

把包链接进 profile，并在 `~/.dsh/profiles/web/cordis.patch.yml` 里挂上：

```yaml
plugins:
  dsh-fingerprint-probe:
    provider: a1          # 要检测的 provider 路由
    modelPattern: gpt-6   # 可选：按子串过滤；面板里可自行改选
    reasoningEffort: null # 默认不发送该字段
    maxTokens: 8000
    timeoutMs: 180000
    concurrency: 1
    spacingMs: 1500
```

`reasoningEffort` 默认为 `null`（不发送该字段）。若路由不接受某个档位，带上它会让每条挑战都失败，看起来像模型不可达——所以默认是省略而不是猜一个值。

## 配置项

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `provider` | `a1` | 默认探测的 provider |
| `models` | `[]` | 显式 `provider/model` 列表，设置后覆盖 `provider` + `modelPattern` |
| `modelPattern` | — | 按子串过滤模型 id |
| `reasoningEffort` | `null` | 转发给路由的推理档位；`null` 表示不发送 |
| `maxTokens` | `8000` | 单条挑战的输出上限 |
| `timeoutMs` | `180000` | 单次请求墙钟预算 |
| `concurrency` | `1` | 并发模型数；网关限流严格，默认串行 |
| `spacingMs` | `1500` | 模型之间与挑战之间的间隔 |

面板里勾选的模型会作为显式列表随请求发送，所以检测永远不会悄悄换成另一组模型。

## 路由

| 路由 | 方法 | 说明 |
| --- | --- | --- |
| `/fingerprint-probe/models` | GET | 模型目录 + 参考库摘要 + 缓存状态。打开面板只调这个，不会触发下载或检测 |
| `/fingerprint-probe/run` | GET | 报告当前检测的状态，立即返回：`idle` / `running`（带已完成的部分结果）/ `done` / `error` |
| `/fingerprint-probe/run` | POST | **启动**检测，立即返回 `202 {phase:"running", id}`；body 为 `{"models": ["provider/model", …]}` |

### 检测跑在后台，不绑在请求上

检测要跑几分钟，而面板随时可能被卸载：`main` 槽一次只渲染一个面板，切换对话时工作区会清掉当前面板。
如果把检测绑在发起它的那个 HTTP 请求上，切走的瞬间这份工作就白做了——这正是以前「切个对话回来就要重新点一次」的原因。

所以主机侧持有唯一的运行状态，`POST` 只负责启动、立刻返回，面板靠轮询 `GET` 读回进度。
切走再切回来时，新挂载的面板会发现检测还在跑并自动接上，已完成的模型也会显示出来，而不是回到一张空白页。
面板的勾选状态存在模块级而不是组件 state 里，所以重新挂载不会把选择重置回默认值。

## 参考数据

- **模型元数据**（8.8 KB）随包发布在 `data/bank-meta.json`，面板无需联网即可列出参考库、报告版本不匹配。
- **检测器二进制**（4.1 MB，其中 3.5 MB 是逐模型参考矩阵）不随包发布，首次使用时从固定 commit 下载并校验 SHA-256，缓存在 `$DSH_HOME/cache/fingerprint-probe/`。每次加载都会重新校验，因为缓存位于仓库之外，一次中断的写入不应该能污染后续检测。

固定的是 commit 而不是分支：`bank.built_at` 必须与检测器的 `bank_built_at` 完全一致，且模型顺序是按位置对应的。指向移动分支的话，拿到不同版本的库不会报错——它会安静地给每个候选贴错标签。

## 测试

```bash
node test/fetch-fixtures.mjs   # 拉取参考回答夹具（16 MB，不入库）
node test/test-detector.mjs
```

测试分三类，只有第三类能证明东西：

1. **单元检查**——解析、阈值、选择解析、路由接线，快且不联网。含一组后台运行的回归检查：`POST` 必须在检测跑完前就返回、`GET` 必须报告在跑的任务、第二次 `POST` 必须顶掉第一次；用「永不 resolve 的 stream」保证处理函数没有偷偷 await。
2. **解码检查**——冻结二进制解出的形状确实是排名器索引的那些。解码错误会表现为 `undefined` 参与运算，而不是抛异常，看起来就像一个合理的分数。
3. **标定检查**——把**真实参考回答**重新打分，断言每个模型自己的回答把它排在第一。这一条才是关键：特征数学里的移植错误不会抛错，它只是把所有人排错。没有这条检查，一个彻底坏掉的检测器看起来和一个正常的一样。

夹具缺失时标定检查会显式跳过并打印原因，套件仍然通过——所以「没下载」不会被误当成「全绿」。
