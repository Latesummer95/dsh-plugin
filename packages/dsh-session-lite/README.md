# dsh-session-lite

精简版会话管理：**侧栏底部一个按钮 + 一个弹窗**，支持搜索、归档、取消归档、打开、删除。

替代 `dsh-session-manager`——后者把 6 个控件 + 1 个溢出菜单挂进了
`conversation.session.header.actions`，也就是**会话标题栏**，所以每个会话顶部都被它占着。

## 为什么能精简这么多

原插件大部分功能，DSH 自己就有：

| 功能 | 原插件 | 现在 |
| --- | --- | --- |
| 打开会话 | 自实现 + 私有 API 兜底 | `uiWorkspace.openSession()` |
| 归档 / 取消归档 | 包装 + 兼容层 | `uiWorkspace.archiveSession()` / `unarchiveSession()` |
| 工作区分组 | 自维护投影 | `workspaces` 服务 |
| **删除会话** | 自实现 | **仍由本插件提供（DSH 没有）** |

所以宿主侧只剩一件事：**删除**。其余全部走 DSH 自带服务——私有 API 依赖从 8 处降到 **0**。

## 对比

|  | dsh-session-manager | dsh-session-lite |
| --- | --- | --- |
| 客户端体积 | 281 KB（其中手写 CSS 60 KB） | **16.6 KB（减少 94%），零样式表** |
| 宿主体积 | 约 71 KB + 12 KB 兼容层 | **15.6 KB** |
| 顶部标题栏占用 | 6 控件 + 溢出菜单 | **0** |
| 宿主路由 | 多个（含迁移、投影扫描） | **1 个（删除）** |
| 设置项 | 有（含更新检查） | **无** |
| 私有 API 依赖 | 8 处 | **0** |
| 界面组件 | 自绘 | 复用 `dsh-client-ui-primitives` |

界面用 DSH 自带的 `Button` / `Input` / `Modal` 渲染，没有自己的 CSS，
所以配色、圆角、字号**自动跟随主题**，不会在换主题后变成一块异色补丁。

## 保留的功能

- **列表**：标题、相对时间（"6 小时前"）、归档标记
- **搜索**：匹配标题、**会话 ID**、工作目录
  （ID 是有意匹配的——用户经常从日志里粘贴 ID，只搜标题会什么都找不到）
- **筛选**：未归档 / 已归档 / 全部
- **操作**：打开、归档、取消归档、删除
- **删除**：两步确认

## 有意去掉的功能

标注、AI 整理、批量操作、预设迁移、会话移动、更新检查器、设置卡片、启动投影扫描。

这些不是"没来得及做"，而是**去掉**：它们正是让原插件变成第二个应用的部分，
而其中没有一个需要留在标题栏上。

## 删除的安全设计

删除是唯一会动文件系统的操作，所以它按下面的顺序走，每一步都有理由：

1. **`assertSessionId`** —— 先拒绝任何可能是路径或特殊目录名的输入
2. **定位并校验** —— 目录层级是 `<root>/<编码后的项目路径>/<会话id>/<工件>`；
   中间那层来自项目 **cwd** 而非会话 id，所以无法从请求推出，只能枚举。
   找到后要求工件**自己的 header 里写着这个 id**——否则仅凭目录名匹配就删除是危险的
3. **`assertSessionDirectory`** —— 对每一层 `lstat` 并重新 realpath，
   拒绝符号链接；这样把某个项目层做成软链也无法让递归删除跑出会话树
4. **拆解** —— 取消 agent（`disposed`，避免被重新唤醒）、flush、detach、通知其它客户端
5. **重新定位** —— 空会话可能在 flush 期间写下第一个工件，不重找会留下看不见的孤儿
6. **再次 `assertSessionDirectory`，然后才 `rm`** —— 校验的价值取决于它的时机

另外：

- **`Origin` 校验**：`no-cors` 的 fetch 和普通表单 POST 都不触发预检，
  所以一个恶意页面能**发出**这个请求（虽然读不到响应）。校验 Origin 才能挡住它。
- **64 KiB 请求体上限**：按累计长度判断，不看 `Content-Length`（那是调用方可控的，
  且分块请求根本没有）。超限直接销毁 socket。
- **按 id 串行**：双击确认按钮会并发两次 `rm -rf`，输的那次会**报告失败**，
  但删除其实成功了。按 id 排队让第二次看到第一次留下的世界；
  不同 id 之间仍然并行。

## 安装

```bash
ln -sfn /path/to/dsh-plugin/packages/dsh-session-lite \
  "$DSH_HOME/profiles/<profile>/node_modules/dsh-session-lite"
```

然后把 `dsh-session-lite` 加进该 profile `package.json` 的
`dsh.profile.bundles`，重启 DSH。

宿主侧改动需要重启（DSH 不监听宿主文件），客户端 bundle 会热重载。

## 测试

```bash
node test/test-delete.mjs   # 15 项：路径发现、越界拒绝、符号链接、队列、请求校验
node test/test-client.mjs    # 11 项：bundle 契约、槽位注册、数据形状
```

删除相关的测试重点覆盖**拒绝**路径：一个能删对会话、但也能删掉会话树外目录的路由，
比一个什么都不做的路由更糟。
